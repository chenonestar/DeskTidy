桌面图标整理程序 · 需求说明

2026-10-27　cyx_98

1背景与目标

目标是：不改动任何桌面文件，把桌面图标按分组显示，并能用键盘在 3 秒内找到并启动任意一项。现状是图标多且无序，找程序只能靠肉眼逐个扫。

要达成的结果：

  • 分组显示：图标归入可命名的分区（如“开发工具”“办公”“文档”“临时文件”），按区域一眼定位。
  • 自动归类：新出现在桌面的图标按规则自动进入对应分组，不需要反复手动整理。
  • 快速查找：全局快捷键呼出搜索框，支持中文拼音首字母（输入 wx 找到“微信”），回车即启动。
  • 可逆：程序退出、崩溃或卸载后，桌面恢复原样，文件一个不少。

V1 明确不做：通用启动器（不扫描开始菜单和全盘程序，只管桌面上的东西）、壁纸与小部件等装饰功能、云同步。

同类产品有 Stardock Fences、腾讯桌面整理、360 桌面助手。自己写的价值在于：无广告和捆绑，归类规则按自己习惯定制，数据完全本地。

2核心设计决策

采用“虚拟视图”方案：桌面文件原地不动，程序关闭系统桌面图标显示，自己读取桌面目录并在桌面层绘制分组面板。这是三种可行方案里最安全、最容易做稳的一种。

方案 做法 优点 缺点 结论
A. 虚拟视图 隐藏系统图标，程序读取桌面目录自绘分组 不碰文件，退出即复原；布局完全自控，不受分辨率变化影响 系统右键菜单、拖放等原生交互需要自己补齐 采用
B. 移动文件 把文件搬进各分组对应的真实文件夹，桌面只留分组窗口 实现简单 文件路径改变，依赖原路径的脚本和程序会出错；软件更新会在桌面重建快捷方式；卸载要搬回 不采用
C. 原生图标定位 画分区背景框，跨进程移动 Explorer 桌面列表里真实图标的坐标（Fences 的做法） 原生交互全部保留 跨进程操作 Explorer，分辨率、DPI、Explorer 重启后布局易乱；实现难度最高 不采用

方案 A 的运行规则：

  1. 启动时关闭系统“显示桌面图标”，记录原状态。
  2. 读取“当前用户桌面”和“公共桌面”两个目录，合并后按分组显示。
  3. 监听两个目录的新增、删除、重命名，面板实时同步。
  4. 正常退出、崩溃、卸载时都恢复系统图标显示（崩溃恢复见非功能需求）。

3功能需求

V1 共 10 项，做完即可替代当前桌面日常使用；V2 补齐原生交互和多显示器，V3 是锦上添花。

编号 功能 说明 版本
F01 桌面项目读取 合并“当前用户桌面”和“公共桌面”；支持 .lnk、.url、.exe、文件夹和普通文件；显示真实图标和名称 V1
F02 分组管理 新建、重命名、删除分组；每个分组是桌面上可拖动、可调大小的面板；删除分组时其中项目回到“未归类” V1
F03 手动归类 拖动图标在分组间移动、在分组内排序；一个项目只属于一个分组 V1
F04 自动归类规则 条件可选扩展名、文件类型（程序/文档/图片/压缩包/文件夹/网址）、名称关键词或正则、快捷方式目标路径；按顺序匹配，首个命中生效；只作用于新出现的项目，不覆盖手动归类；另有“按规则重新整理全部”按钮 V1
F05 未归类区 不命中任何规则的新项目进入“未归类”分组并高亮，直到用户处理 V1
F06 快速搜索 全局快捷键呼出（默认 Ctrl+Alt+D，可改）；匹配名称、拼音全拼、拼音首字母；上下键选择，回车启动，Esc 关闭 V1
F07 启动与常用操作 双击或回车打开；右键菜单含打开、以管理员身份运行、打开所在位置、重命名、删除到回收站、属性 V1
F08 布局持久化 分组位置、大小、项目归属和排序全部保存，重启后完全还原 V1
F09 系统图标隐藏与恢复 启动时隐藏系统桌面图标，退出时恢复；托盘可临时切回原生桌面 V1
F10 托盘与自启 托盘图标提供设置、临时显示原生桌面、退出；开机自启开关 V1
F11 分组折叠 分组可折叠为标题栏；双击桌面空白处一键收起或展开全部 V2
F12 完整系统右键菜单 显示与资源管理器一致的右键菜单，含 7-Zip、Git 等第三方菜单项 V2
F13 拖放进出 从其他窗口拖文件到分组，即放到桌面并归入该分组；从分组拖出到其他程序（如拖附件进邮件） V2
F14 多显示器与 DPI 每个显示器独立布局；拔插显示器或改分辨率后，分组自动收回可见区域 V2
F15 使用统计 记录启动次数和最近使用时间；分组内可按常用度排序；搜索结果按使用频率加权 V2
F16 导入导出 规则和布局导出为 JSON，换机或重装后导入 V2
F17 闲置项提示 N 天未使用的项目标记出来，可一键移入“闲置”分组 V3
F18 外观设置 分组背景颜色、透明度、毛玻璃，图标大小 V3
F19 文件夹映射分组 一个分组直接显示某个真实文件夹的内容，不限于桌面 V3

4非功能需求

第一条硬性要求：程序在任何情况下都不能让桌面文件丢失，也不能让用户面对一个“图标全没了”的桌面。

类别 要求
文件安全 程序自身从不移动、改写桌面文件；只有用户在菜单中明确选择重命名或删除时才操作，删除一律进回收站
崩溃恢复 一个极小的守护进程监视主进程，主进程异常退出后 5 秒内恢复系统图标显示；启动时检查上次是否异常退出
Explorer 重启 监听 TaskbarCreated 消息，Explorer 重启后 5 秒内重新挂回桌面层并保持隐藏系统图标
桌面层行为 分组面板始终在普通窗口之下；按 Win+D 或“显示桌面”后面板仍可见、可操作
性能 冷启动到面板显示 ≤ 2 秒；空闲 CPU 接近 0%；内存 ≤ 150 MB；桌面 500 个项目时搜索响应 ≤ 50 毫秒
兼容范围 Windows 10 x64（1903 及以上）；DPI 缩放 100%–200%；Windows 11 尽量兼容，不作为验收条件
权限 普通用户权限运行，不需要管理员；“以管理员身份运行”只作用于被启动的程序
数据存储 配置存于 %APPDATA% 下的 JSON 文件；写入用“临时文件 + 重命名”保证原子性，保留最近 5 份备份
项目标识 以文件路径识别项目；重命名通过目录监听事件跟随，分组归属不丢失

5技术方案建议

推荐 Wails v2：Go 负责 Win32 调用和文件监听，React + TypeScript 负责界面，渲染用系统自带的 WebView2。这个组合正好对应 TypeScript 为主、Go 为辅的技能栈，体积和常驻内存都远小于 Electron。

方案 常驻内存（估计） 调 Win32 结论
Wails v2（Go + React） 约 80–120 MB golang.org/x/sys/windows 直接调用，COM 用 go-ole 推荐
Tauri（Rust + React） 约 60–100 MB windows-rs，最完整 备选，需要 Rust
Electron 约 200 MB 以上 需要 Node 原生模块 不推荐，常驻桌面太重
C# + WPF 约 60–100 MB 最方便 备选，换语言

“挂到桌面层、Win+D 不隐藏”这部分能力，桌面备忘程序同样需要，建议做成独立 Go 包，两个项目共用。

关键实现点：

能力 实现方式
定位桌面目录 SHGetKnownFolderPath，取 FOLDERID_Desktop 和 FOLDERID_PublicDesktop
目录监听 ReadDirectoryChangesW（fsnotify 封装），事件去抖 300 毫秒
图标提取 IShellItemImageFactory::GetImage，按“路径 + 修改时间”缓存为 PNG
快捷方式解析 IShellLink 读取目标路径，供 F04 的“目标路径”规则使用
隐藏/恢复系统图标 向桌面 SHELLDLL_DefView 窗口发送切换图标显示的命令，再检查 SysListView32 可见状态确认结果
启动与管理员运行 ShellExecuteEx，verb 分别为 open、runas、properties
打开所在位置 SHOpenFolderAndSelectItems
删除到回收站 IFileOperation，带 FOFX_RECYCLEONDELETE
全局快捷键 RegisterHotKey
拼音搜索 前端用 pinyin-pro 为每个名称生成全拼和首字母索引
开机自启 写 HKCU 下的 Run 注册表项

6技术风险与预研项

动手写 V1 之前，先用一个最小 Demo 验证第 1、4、5 项；第 1 项不通，整体方案就要调整。第 2、3 项属于 V2，可以等 V1 完成后再验证。

# 风险 预研方式 退路
1 面板挂到桌面层后能否正常接收鼠标键盘；Win+D 后是否仍可见 Demo 对比两种做法：父窗口设为桌面 WorkerW；普通窗口置底并拦截 WM_WINDOWPOSCHANGING 普通置底窗口 + 监听前台窗口变化，Win+D 后自动重新显示
2 完整系统右键菜单（F12）需要 IContextMenu2/3 及菜单消息转发，Go 下实现繁琐 用 go-ole 调 IContextMenu，TrackPopupMenu 弹出 V1 自定义菜单已覆盖常用操作；必要时用 C 写一个小 DLL
3 WebView2 不能把本地文件作为系统拖放源（F13 拖出） 鼠标按下后由 Go 侧调用 DoDragDrop 接管拖拽 用“复制文件”菜单代替拖出
4 隐藏系统图标依赖未公开的 Explorer 行为，系统更新后可能失效 在 Win10 22H2 和 Win11 各验证一次 改注册表 HideIcons 值后通知 Explorer 刷新
5 WebView2 多进程，内存可能超过 150 MB Demo 加载 300 个图标后测量常驻内存 图标懒加载、限制缓存；仍超标则改用 Tauri
