DeskTidy · 需求说明

2026-10-27 初稿 · 2026-10-29 修订　cyx_98

1背景与目标

DeskTidy 是一个 Windows 桌面图标整理程序，绿色便携，解压即用。目标是：不改动任何桌面文件，把桌面图标按分组显示，并能用键盘在 3 秒内找到并启动任意一项。现状是图标多且无序，找程序只能靠肉眼逐个扫。

要达成的结果：

  • 分组显示：图标归入可命名的分区（如“开发工具”“办公”“文档”“临时文件”），按区域一眼定位。
  • 自动归类：新出现在桌面的图标按规则自动进入对应分组，不需要反复手动整理。
  • 快速查找：全局快捷键呼出搜索框，支持中文拼音首字母（输入 wx 找到“微信”），回车即启动。
  • 可逆：程序退出、崩溃、卡死、断电或被删除后，都能回到原生桌面，文件一个不少，图标位置不变。

V1 明确不做：通用启动器（不扫描开始菜单和全盘程序，只管桌面上的东西）、壁纸与小部件等装饰功能、云同步、安装程序（绿色便携，解压即用）。

同类产品有 Stardock Fences、腾讯桌面整理、360 桌面助手。自己写的价值在于：无广告和捆绑，归类规则按自己习惯定制，数据完全本地。

2核心设计决策

采用“虚拟视图”方案：桌面文件原地不动，程序临时隐藏系统桌面图标，自己读取桌面目录并在桌面层绘制分组面板。这是三种可行方案里最安全、最容易做稳的一种。

方案 做法 优点 缺点 结论
A. 虚拟视图 临时隐藏系统图标，程序读取桌面目录自绘分组 不碰文件，退出即复原；布局完全自控，不受分辨率变化影响 系统右键菜单、拖放等原生交互需要自己补齐 采用
B. 移动文件 把文件搬进各分组对应的真实文件夹，桌面只留分组窗口 实现简单 文件路径改变，依赖原路径的脚本和程序会出错；软件更新会在桌面重建快捷方式；卸载要搬回 不采用
C. 原生图标定位 画分区背景框，跨进程移动 Explorer 桌面列表里真实图标的坐标（Fences 的做法） 原生交互全部保留 跨进程操作 Explorer，分辨率、DPI、Explorer 重启后布局易乱；实现难度最高 不采用

方案 A 的运行规则：

  1. 启动后先显示分组面板，确认加载正常后才隐藏系统桌面图标；隐藏是临时的，不改系统设置（见 3.1）。
  2. 读取“当前用户桌面”和“公共桌面”两个目录，合并后按分组显示。
  3. 监听两个目录的新增、删除、重命名，面板实时同步。
  4. 任何异常的最终结果都是回到原生桌面（见第 3 节）。

3安全与恢复设计

总原则：出现任何异常，原桌面的文件内容和图标位置都不受影响，并且一定能回到原生桌面。为此遵循三条准则：

  1. 失败即回到原生桌面：崩溃、卡死、断电、Explorer 重启、界面加载失败，任何意外的最终结果都是系统原生桌面，而不是“图标没了、面板也没了”。
  2. 对系统只做临时、可撤销的修改，先记录再修改：改动任何系统状态之前，先把原值和恢复方法写入 state.json。
  3. 多层兜底：不依赖单一恢复机制，一层失效还有下一层。

3.1 隐藏系统图标的方式

采用临时隐藏：对桌面的 SysListView32 窗口调用 ShowWindow(SW_HIDE)，不改“显示桌面图标”系统设置。隐藏状态只存在于 Explorer 进程内存中，Explorer 重启、注销或重启电脑后图标自动恢复显示，最坏情况下系统也会自己回到原桌面。

  • 用 SetWinEventHook 监听 EVENT_OBJECT_SHOW：Explorer 自行重新显示图标列表时，在面板正常的前提下再次隐藏。
  • 用户原本就关闭了“显示桌面图标”的，DeskTidy 不改动它，退出时保持原样。
  • 启动顺序：显示分组面板 → 项目加载完成 → 向守护进程报告就绪 → 拍图标位置快照 → 写 state.json → 隐藏系统图标。任何一步失败都不隐藏。

退路（仅当临时隐藏在预研中被证明不可行时采用）：切换系统“显示桌面图标”设置，这会持久写入注册表 HideIcons。此时必须先写恢复再修改：隐藏前把原 HideIcons 值写入 state.json，并在 HKCU\Software\Microsoft\Windows\CurrentVersion\RunOnce 登记一条恢复命令；正常恢复后删除该命令。这样即使断电，下次登录也会先执行恢复，且不受开机自启开关影响。

3.2 异常场景与恢复

场景 保障措施
正常退出、托盘“显示原生桌面” 立即恢复系统图标显示
主进程崩溃 守护进程发现主进程退出后，5 秒内恢复
主进程卡死、界面白屏 前端每秒经主进程向守护进程发送心跳，超过 5 秒未收到即恢复；进程还在不代表程序正常
WebView2 渲染进程崩溃 收到 ProcessFailed 事件立即恢复，同时由心跳兜底
启动或加载失败 完成就绪握手之前从不隐藏系统图标
Explorer 重启 系统图标随 Explorer 重启自动显示；DeskTidy 收到 TaskbarCreated 后重新挂回面板，确认正常后再隐藏
断电、强制关机 临时隐藏方案下，重启后自然恢复；退路方案下，由 RunOnce 在下次登录时恢复；DeskTidy 启动时读 state.json，发现上次未正常退出则先恢复再继续
连续崩溃 连续 3 次异常退出后进入安全模式：只显示分组面板，不隐藏系统图标，并提示用户
用户手动逃生 应急快捷键 Ctrl+Alt+Shift+D（由守护进程注册，主进程卡死也可用）；程序目录内的“恢复原桌面.cmd”；按住 Shift 启动进入安全模式
不再使用、删除程序 先用托盘“退出并清理”：恢复原桌面并删除 DeskTidy 写过的注册表项，然后删除程序目录即可
程序所在可移动磁盘被拔出 见第 4 节“可移动磁盘”和风险第 7 项

3.3 原桌面图标位置保护

DeskTidy 自己不移动系统图标，但隐藏期间 Explorer 可能因分辨率变化、拔插显示器、新文件加入等原因自行重排。因此：

  • 每次隐藏前，通过公开的 COM 接口读取每个图标的坐标，连同分辨率、DPI、“自动排列”和“对齐到网格”状态保存为快照，保留最近 5 份。不使用跨进程读写 Explorer 内存的做法。
  • 托盘提供“恢复原桌面图标位置”，可选择某一份快照写回。
  • 同时记录桌面文件清单（路径、大小、修改时间），用于自检“文件一个不少”和排查问题。

3.4 文件操作

  • DeskTidy 从不自动写入桌面目录。写桌面文件的代码集中在一个模块，只能由用户在菜单中明确选择的重命名、删除调用；删除一律进回收站。
  • 公共桌面（C:\Users\Public\Desktop）默认需要管理员权限才能修改。DeskTidy 本身保持普通权限，由 IFileOperation 像资源管理器一样弹出 UAC 确认；这类项目的菜单项显示盾牌图标。

4绿色便携与数据存放

DeskTidy 是绿色便携程序：无安装程序，所有数据写在程序目录下的 data\ 中，不写程序目录以外的文件。

DeskTidy\
├─ DeskTidy.exe                 主程序
├─ DeskTidyGuard.exe            守护进程
├─ 恢复原桌面.cmd               调用 DeskTidyGuard.exe --restore，不依赖主程序
└─ data\
   ├─ config.json               分组、规则、布局、使用统计（可随目录带到别的电脑）
   ├─ backup\                   config.json 最近 5 份备份
   └─ local\<计算机名>-<用户名>\  只属于这台电脑、这个用户的数据
      ├─ state.json             当前对系统做了哪些修改（恢复依据）
      ├─ snapshots\             桌面图标位置快照，最近 5 份
      ├─ inventory\             桌面文件清单
      ├─ icon-cache\            图标缓存
      ├─ webview2\              WebView2 用户数据目录
      └─ logs\
事项 要求
目录可写检查 启动时在 data\ 试写临时文件。不可写（如放在 Program Files 或只读介质上）时不隐藏系统图标，提示把程序移到可写位置；不悄悄改写到 %APPDATA%，避免配置“找不到”
跨电脑携带 config.json 中的项目路径相对“用户桌面”“公共桌面”保存，复制目录到别的电脑或别的用户仍可用；本机状态放在 local\<计算机名>-<用户名>\ 下，不会被另一台电脑误用
注册表痕迹 只有两处，都在 HKCU：开机自启（用户打开开关时写 Run）；退路方案隐藏期间的 RunOnce。托盘“退出并清理”恢复原桌面并删除这两项
移动程序目录 自启已开启时，每次启动校验 Run 中的路径，与当前路径不同就更新
单实例 按当前用户会话加互斥体，两份便携副本不会同时运行、互相隐藏或恢复图标
可移动磁盘 检测到程序位于可移动磁盘时给出提示；收到“安全弹出”请求时先恢复原桌面再退出。直接拔盘时进程可能来不及处理，见风险第 7 项
WebView2 运行时 启动时检测 WebView2 Runtime（早期 Win10 可能没有），缺失时不隐藏系统图标并提示安装；用户数据目录指向 data\local\…\webview2

5功能需求

V1 共 11 项，做完即可替代当前桌面日常使用；V2 补齐原生交互和多显示器，V3 是锦上添花。编号保持稳定，新增项顺延编号。

编号 功能 说明 版本
F01 桌面项目读取 合并“当前用户桌面”和“公共桌面”；支持 .lnk、.url、.exe、文件夹和普通文件；显示真实图标和名称；公共桌面项目加角标，同名项目同时显示，鼠标悬停显示完整路径 V1
F02 分组管理 新建、重命名、删除分组；每个分组是桌面上可拖动、可调大小的面板；删除分组时其中项目回到“未归类” V1
F03 手动归类 拖动图标在分组间移动、在分组内排序；一个项目只属于一个分组 V1
F04 自动归类规则 条件可选扩展名、文件类型（程序/文档/图片/压缩包/文件夹/网址）、名称关键词或正则、快捷方式目标路径；按顺序匹配，首个命中生效；只作用于新出现的项目，不覆盖手动归类；另有“按规则重新整理全部”按钮；正则使用 Go（RE2）语法，保存时校验 V1

F07 启动与常用操作 双击或回车打开；右键菜单含打开、以管理员身份运行、打开所在位置、重命名、删除到回收站、属性；需要管理员权限的操作显示盾牌图标，由系统弹出 UAC 确认 V1
F08 布局持久化 分组位置、大小、项目归属和排序全部保存到程序目录 data\config.json，重启后完全还原 V1
F09 系统图标隐藏与恢复 面板就绪并拍下图标位置快照后，临时隐藏系统桌面图标（不改系统设置）；退出时恢复；托盘可临时切回原生桌面（见 3.1） V1
F10 托盘与自启 托盘图标提供设置、临时显示原生桌面、恢复原桌面图标位置、退出、退出并清理；开机自启开关 V1
F20 恢复原桌面 应急快捷键 Ctrl+Alt+Shift+D（守护进程注册，主进程卡死也可用）；程序目录内“恢复原桌面.cmd”，不依赖主程序；按住 Shift 启动进入安全模式；从快照恢复图标位置（见 3.2、3.3） V1
F11 分组折叠 分组可折叠为标题栏；双击桌面空白处一键收起或展开全部 V2

F13 拖放进出 从其他窗口拖文件到分组，即放到桌面并归入该分组；从分组拖出到其他程序（如拖附件进邮件） V2
F14 多显示器与 DPI 每个显示器独立布局；拔插显示器或改分辨率后，分组自动收回可见区域 V2

F17 闲置项提示 N 天未使用的项目标记出来，可一键移入“闲置”分组 V3
F18 外观设置 分组背景颜色、透明度、毛玻璃，图标大小 V3
F19 文件夹映射分组 一个分组直接显示某个真实文件夹的内容，不限于桌面 V3

6非功能需求

第一条硬性要求：程序在任何情况下都不能让桌面文件丢失或图标位置错乱，也不能让用户面对一个“图标全没了”的桌面。

类别 要求
文件安全 程序自身从不移动、改写桌面文件；只有用户在菜单中明确选择重命名或删除时才操作，删除一律进回收站（见 3.4）
回到原桌面 任何异常的最终结果都是原生桌面（见 3.2）；断电或强制关机后，下次登录必须看到原生桌面
崩溃与卡死 守护进程同时监视主进程退出和心跳，异常后 5 秒内恢复系统图标显示；连续 3 次异常退出后进入安全模式
Explorer 重启 监听 TaskbarCreated 消息，Explorer 重启后 5 秒内重新挂回桌面层，确认面板正常后再隐藏系统图标
图标位置 每次隐藏前拍位置快照，保留最近 5 份，可一键写回（见 3.3）
桌面层行为 分组面板始终在普通窗口之下；按 Win+D 或“显示桌面”后面板仍可见、可操作
性能 冷启动到面板显示 ≤ 2 秒；空闲 CPU 接近 0%；内存 ≤ 150 MB；桌面 500 个项目时搜索响应 ≤ 50 毫秒
兼容范围 Windows 10 x64（1903 及以上），需要 WebView2 Runtime；DPI 缩放 100%–200%；Windows 11 尽量兼容，不作为验收条件
权限 普通用户权限运行，不需要管理员；“以管理员身份运行”只作用于被启动的程序；修改公共桌面项目时由系统弹出 UAC 确认
绿色便携 不写程序目录以外的文件；注册表只用 HKCU 下的 Run 和 RunOnce；“退出并清理”后删除目录即无残留（见第 4 节）
数据存储 存于程序目录 data\ 下的 JSON 文件；写入用“临时文件 + 重命名”保证原子性，保留最近 5 份备份
项目标识 以相对桌面根的路径识别项目，另记 NTFS 文件 ID 和快捷方式目标；运行中的重命名通过目录监听跟随；启动时核对一次，程序关闭期间的改名按文件 ID 和目标路径匹配；找不到的项目记录保留 30 天，同路径重新出现（如软件更新重建快捷方式）时回到原分组

7技术方案建议

推荐 Wails v2：Go 负责 Win32 调用和文件监听，React + TypeScript 负责界面，渲染用系统自带的 WebView2。这个组合正好对应 TypeScript 为主、Go 为辅的技能栈，体积和常驻内存都远小于 Electron。

方案 常驻内存（估计） 调 Win32 结论
Wails v2（Go + React） 约 80–120 MB golang.org/x/sys/windows 直接调用，COM 用 go-ole 推荐
Tauri（Rust + React） 约 60–100 MB windows-rs，最完整 备选，需要 Rust
Electron 约 200 MB 以上 需要 Node 原生模块 不推荐，常驻桌面太重
C# + WPF 约 60–100 MB 最方便 备选，换语言

“挂到桌面层、Win+D 不隐藏”这部分能力，桌面备忘程序同样需要，建议做成独立 Go 包，两个项目共用。

打开所在位置 SHOpenFolderAndSelectItems

全局快捷键 RegisterHotKey；注册失败时提示并打开设置
规则匹配 在 Go 侧用 regexp（RE2 语法，线性时间，写错的正则也不会卡死程序），保存规则时校验
拼音搜索 前端用 pinyin-pro 为每个名称生成全拼和首字母索引
开机自启 写 HKCU 下的 Run 注册表项，值为当前 DeskTidy.exe 完整路径，每次启动校验

8技术风险与预研项

动手写 V1 之前，先用一个最小 Demo 验证第 1、4、5、6 项：第 1 项不通，整体方案就要调整；第 4 项不通，改用 3.1 中的退路方案。第 2、3 项属于 V2，可以等 V1 完成后再验证；第 7 项在 V1 开发中验证。

# 风险 预研方式 退路
1 面板挂到桌面层后能否正常接收鼠标键盘；Win+D 后是否仍可见 Demo 对比两种做法：父窗口设为桌面 WorkerW；普通窗口置底并拦截 WM_WINDOWPOSCHANGING 普通置底窗口 + 监听前台窗口变化，Win+D 后自动重新显示
2 完整系统右键菜单（F12）需要 IContextMenu2/3 及菜单消息转发，Go 下实现繁琐 用 go-ole 调 IContextMenu，TrackPopupMenu 弹出 V1 自定义菜单已覆盖常用操作；必要时用 C 写一个小 DLL
3 WebView2 不能把本地文件作为系统拖放源（F13 拖出） 鼠标按下后由 Go 侧调用 DoDragDrop 接管拖拽 用“复制文件”菜单代替拖出
4 临时隐藏（SW_HIDE）依赖未公开的 Explorer 行为：桌面刷新、改分辨率、用户右键切换“显示桌面图标”后是否被重新显示；隐藏后桌面空白处的右键和双击是否正常 在 Win10 22H2 和 Win11 各验证一次 改为切换“显示桌面图标”设置（HideIcons），配合 state.json 和 RunOnce 保证可恢复（见 3.1）
5 WebView2 多进程，内存可能超过 150 MB Demo 加载 300 个图标后测量常驻内存 图标懒加载、限制缓存；仍超标则改用 Tauri
6 图标位置快照：IFolderView 能否在关闭“自动排列”时准确读取和写回坐标；多显示器下坐标是否正确 Demo 读取坐标、手动打乱、写回后比对 备份注册表 HKCU\Software\Microsoft\Windows\Shell\Bags\1\Desktop；恢复时先结束 Explorer，写回后再启动
7 程序在可移动磁盘上运行时被直接拔出，主进程和守护进程可能同时退出，系统图标保持隐藏，直到 Explorer 重启或注销 在 U 盘上运行后直接拔出，观察守护进程能否存活并完成恢复 在可移动磁盘上运行时不隐藏系统图标，只显示分组面板
